# 📰 Simple News

A modern, scalable Flutter news application built with **Clean Architecture**, **Dart 3 (Sealed Classes & Pattern Matching)**, and **Riverpod 3 (Code Generation)**.

This repository demonstrates how to architect a real-world Flutter application with strict separation of concerns, deterministic testability, functional error handling, and robust network resilience.

---

## 🏗️ Architecture Overview

The project adheres to **Uncle Bob's Clean Architecture** principles, enforcing the **Dependency Rule** (all source code dependencies point inward toward high-level business policies).

```
       ┌──────────────────────────────────────────────┐
       │             PRESENTATION LAYER               │
       │    (Widgets, Screens, Riverpod Notifiers)    │
       │  ┌────────────────────────────────────────┐  │
       │  │               DATA LAYER               │  │
       │  │   (Repositories Impl, Data Sources)    │  │
       │  │  ┌──────────────────────────────────┐  │  │
       │  │  │          DOMAIN LAYER            │  │  │
       │  │  │     (Entities, Use Cases)        │  │  │
       │  │  │    [ Pure Dart • Inner Core ]    │  │  │
       │  │  └──────────────────────────────────┘  │  │
       │  └────────────────────────────────────────┘  │
       └──────────────────────────────────────────────┘
```

### Key Architectural Highlights:
- **🟢 Domain Layer (Pure Dart)**: Zero Flutter or HTTP dependencies. Contains business entities (`News`), abstract repository contracts (`NewsRepository`), and single-responsibility Use Cases (`GetNewsUsecase`).
- **🟡 Data Layer**: Manages external data from REST APIs via `NewsRemoteDataSource`, DTOs (`NewsModel`) with `json_serializable`, and mappers to domain entities. Catches `DioException` and converts them into typed domain `AppFailure`s.
- **🔵 Presentation Layer**: Reactive UI consuming `AsyncNotifier` generated by `riverpod_generator`. Handles `AsyncValue` states (`loading`, `data`, `error`) declaratively.
- **⚪ Core / Cross-Cutting**: Dart 3 Sealed Classes `Result<T>` (`Success` vs `Failure`), typed failure hierarchy, network client abstraction (`DioApiClient`), and logging via `Talker`.
- **🔌 Dependency Injection**: Pure Dart DI container using Riverpod `Provider` without requiring `BuildContext`.

## 📁 Project Structure

```
lib/
├── core/                         # Cross-cutting concerns & shared abstractions
│   ├── config/env.dart           # Environment variables (.env)
│   ├── di/network_di.dart        # Core network providers (Dio, ApiClient)
│   ├── error/
│   │   ├── failures.dart         # Domain failure hierarchy (AppFailure)
│   │   └── exception_mapper.dart # Translates Dio exceptions to Failures
│   ├── network/
│   │   ├── api_client.dart       # Abstract HTTP client contract
│   │   ├── dio_api_client.dart   # Dio implementation with Talker logger
│   │   └── interceptors/         # Auth & Header interceptors
│   ├── result/
│   │   └── result.dart           # Functional Result<T> sealed class
│   └── router/
│       ├── app_router.dart       # Declarative GoRouter configuration
│       └── app_routes.dart       # Route path constants
│
├── domain/                       # 🟢 DOMAIN LAYER (Pure Dart)
│   ├── entities/news.dart        # News business model (Equatable)
│   ├── repositories/             # Abstract Repository Contracts
│   │   └── news_repository.dart
│   └── usecases/                 # Single-responsibility business actions
│       └── get_news_usecase.dart
│
├── data/                         # 🟡 DATA LAYER (Data Sources & Mappers)
│   ├── data_sources/remote/      # REST API communication
│   │   └── news_remote_data_source.dart
│   ├── models/                   # JSON serializable DTOs
│   │   ├── news_model.dart
│   │   └── news_model.g.dart
│   ├── mappers/                  # Model -> Entity converters
│   │   └── news_mapper.dart
│   └── repositories/             # Repository Implementations
│       └── news_repository_impl.dart
│
├── presentation/                 # 🔵 PRESENTATION LAYER (Flutter UI & State)
│   ├── pages/
│   │   ├── news_list_page.dart   # News feed screen
│   │   └── news_detail_page.dart # In-app WebView reader
│   ├── providers/                # Riverpod AsyncNotifier
│   │   ├── news_notifier.dart
│   │   └── news_notifier.g.dart
│   └── widgets/                  # Reusable presentation widgets
│       └── news_item_widget.dart
│
├── di/                           # Dependency Injection wiring
│   └── news_di.dart              # Riverpod providers connecting layers
└── main.dart                     # App entry point with ProviderScope
```

## 🛠️ Tech Stack & Libraries

| Category | Package / Tool | Purpose |
| :--- | :--- | :--- |
| **Language & Core** | `Dart 3.x` | Sealed classes, pattern matching, class modifiers |
| **State & DI** | `flutter_riverpod`, `riverpod_annotation`, `riverpod_generator` | Reactive asynchronous state management and compile-time safe DI |
| **Networking** | `dio`, `talker_dio_logger`, `talker_flutter` | HTTP client with interceptors, timeouts, and advanced structured logging |
| **Serialization** | `json_annotation`, `json_serializable`, `build_runner` | Compile-time safe code-generated JSON parsing |
| **Domain Utilities** | `equatable` | Value equality for domain entities and failures |
| **Routing & Media** | `go_router`, `cached_network_image`, `webview_flutter` | Declarative routing, image caching, and in-app article reading |
| **Testing** | `flutter_test`, `mockito` | Isolated unit testing across Domain, Data, and Core layers |

## ⚡ Getting Started

### Prerequisites
- [Flutter SDK](https://docs.flutter.dev/get-started/install) (`^3.12.2` or later)
- [Dart SDK](https://dart.dev/get-dart) (`^3.12.2` or later)
- News API Key from [NewsAPI.org](https://newsapi.org/)

### 1. Clone the Repository
```bash
git clone https://github.com/your-username/simple_news.git
cd simple_news
```

### 2. Configure Environment Variables
Create a `.env` file in the root directory:
```env
NEWS_API_KEY=your_news_api_key_here
NEWS_API_BASE_URL=https://newsapi.org/v2
IMAGE_PLACEHOLDER_URL=https://placehold.net/400x400.png
```

### 3. Install Dependencies & Generate Code
```bash
flutter pub get
dart run build_runner build -d
```

### 4. Run the Application
```bash
flutter run
```

## 🧪 Running Automated Tests

This project features comprehensive unit test coverage across Domain, Data, and Core layers using **Mockito**:

```bash
flutter test
```

### Test Suites Included:
- `test/domain/usecases/get_news_test.dart` — Tests Use Case interactions with mock repositories.
- `test/data/repositories/news_repository_impl_test.dart` — Tests entity mapping and `DioException` translation.
- `test/data/data_sources/news_remote_data_source_test.dart` — Tests REST API parsing from mock HTTP clients.
- `test/data/models/news_model_test.dart` — Tests JSON deserialization.
